# PRODUCT DECISIONS — OWNER RESPONSES RECORDED

**Release status: 2026-10-01 category-first Student flow approved; technical release gate still requires candidate.5 PostgreSQL/browser verification.** The owner confirmed category-first first registration, Student self-enrollment into active categories, category-scoped level selection, and server-side enforcement. Existing Kızılay data-preservation and branch-isolation rules remain unchanged.

1. **One combined weekly cap:** Istanbul Monday–Sunday; count all active dated child reservations across categories, even sessions already completed during that week; student cancellation before start frees entitlement; next week starts fresh. Every branch starts unrestricted until its Admin explicitly sets the cap in Settings; `0` means unlimited. Existing Kızılay remains unchanged until its Admin sets a cap.
2. **Individual override and Admin-cancelled sessions:** Admin may set a different Student cap (`0` unlimited, `null` inherit). A dated Admin-cancelled session temporarily does not count; confirmed bookings remain grandfathered if restored, while new bookings above the cap are blocked.
3. **Category-first first registration — OWNER CONFIRMED 2026-10-01:** the public first-registration flow shows every active branch category first, then only that category's active levels. General English shows A1–C2, Junior English Junior 1–6, Teenage English Teenage 1–5, and Admin-created categories show their own levels. Level-free categories require no level selection. Public booking is validated server-side against the selected category, selected level, slot category, slot eligibility, capacity, dates and weekly quota.
4. **Authenticated Student self-enrollment — OWNER CONFIRMED 2026-10-01:** an authenticated Student may add any active category they have never been enrolled in and choose that category's initial level. Existing active enrollment cannot be silently changed through self-enrollment; use the level-change request flow. An Admin-disabled/inactive enrollment cannot be reactivated by the Student and requires Admin action. Category archive also blocks new access. Admin enrollment controls remain available.
5. **Existing Student panel:** all active categories are visible. Enrolled categories show the Student's official level and are bookable according to server-authoritative eligibility. Unenrolled active categories expose a self-enrollment action. Schedule cards remain category-labelled, and booking authorization always comes from the server rather than browser state.
6. **Student authentication:** passwordless login is retained for now, with the known impersonation risk. The UI is category-first and level-scoped: name + surname + Turkish phone + one active enrolled category + that category's official level (when levelled). A backward-compatible General English level-only API path remains for older clients/tests. No SMS/OTP is introduced without approval.
7. **Additional levels and change requests:** Admin grants extra levels within an enrolled category until manually revoked. One pending Student level-change request per category; Admin approves/rejects; direct Admin category-level update supersedes the pending request. Existing confirmed bookings and historical snapshots are preserved.
8. **Topology and language:** one repository/one existing Hetzner VM, three independent Coolify apps with private branch databases, original hostname remains Kızılay alias; independent Admin/Teacher/Student records, blank new-branch timetables, Student TR default + EN switch, Teacher EN default + TR switch, Admin TR.

Already explicit requirements retained: Teacher own+active-student tile behavior, Admin exact-date occupancy, no copied branch data, no extra VM/external messaging, no destructive operations against Kızılay, immutable branch identity, server-side concurrency controls, history-preserving soft archive, and restored-copy preservation checks before production.
